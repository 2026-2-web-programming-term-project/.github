# 통합 WBS

연구실 GPU 서버 자원 예약 및 실시간 모니터링 시스템의 개발 작업 계획입니다. **이 문서 한 곳에서 일정·선행 관계·완료 기준·상태를 관리하고, 저장소별 README는 담당 구간으로 연결합니다.**

- 기준일: 2026-11-02 / 버전: 1.0
- 시간대: 한국 표준시(KST, UTC+09:00). 아래 월일 표기는 모두 2026년입니다.
- 기간은 계획값이며 제출 마감은 고정입니다. 병행 구간은 작업 가능한 기간을 뜻하며 투입 인원이나 공수를 확정한 일정은 아닙니다.
- 선행 ID는 착수 전에 완료해야 하는 작업입니다. 같은 날짜의 인계는 선행 작업을 검증한 뒤 후행 작업에 착수합니다.
- 상태는 `예정 → 진행 → 검증 중 → 완료`로 관리합니다. 완료에는 코드·문서·테스트·배포 결과 등 확인 가능한 근거를 남깁니다.

ASG는 웹 애플리케이션 처리 계층의 용량을 늘립니다. 연구실 GPU 장비 수와 예약 가능 자원은 별도로 관리합니다. ALB·ACM을 도입하는 안에서는 외부 TLS 연결을 ALB에서 종료하고 내부 암호화 여부를 INF-01에서 정합니다.

## 진행 상태 관리

1. 작업을 시작하면 해당 행을 `진행`으로 바꾸고, 일정·선행 조건 변경도 같은 문서에 반영합니다.
2. 구현 후 완료 기준에 맞는 확인을 수행하고 `검증 중`으로 표시합니다.
3. 완료 기준을 충족하면 `완료`로 변경하고 마지막 열 또는 작업명에 PR·커밋·검증 문서 링크를 추가합니다.
4. 완료한 작업의 마감·기준이 바뀌면 재검증 여부를 기록합니다. 날짜가 지났다는 이유로 완료 처리하지 않습니다.
5. 새 이슈·PR을 만들 때 관련 WBS ID를 사용합니다. 별도 저장소에 일정·상태를 복사해 두 번째 WBS를 만들지 않습니다.

## 범위와 미확정 사항

- 회원·예약·조회·변경은 소속 연구실과 권한을 기준으로 제한하며 저장 시 서버에서 다시 검사합니다.
- 실제 GPU 상태와 예약 상태를 구분합니다. GPU 작업 자동 실행·강제 중지, 대기자 자동 예약은 범위에 포함하지 않습니다.
- 정책의 1시간 단위·8시간 제한·10분 전 알림과 가입 검증 수치는 설계 제안값입니다. 실제 적용값은 API-01·API-09에서 확정·관리합니다.
- MySQL·MariaDB 선택은 DB-01, 추가 저장소·메시징·공유 상태·TLS·HA·부하 합격 기준은 INF-01에서 결정합니다.
- 초기 프로젝트 파일 존재는 기능·빌드·배포 검증 완료가 아닙니다. 서비스 기능 작업은 검증 전이므로 현재 `예정`으로 기록합니다.
- 현재 인프라는 설계 방향 단계입니다. 운영 배포·실측 처리량·장애 복구 능력을 완료 사실로 표시하지 않습니다.
